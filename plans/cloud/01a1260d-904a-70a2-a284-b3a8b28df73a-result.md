## Summary

New package `@nera-static/plugin-feed` 1.0.0, built from an empty repo in the
shape of plugin-sitemap. `getAssets` writes one Atom feed per language
(`feed.xml`, `<lang>/feed.xml`; RSS 2.0 at `rss.xml` with `format: rss|both`)
into `.nera-cache/feed/` and hands the files to core. `getAppData` guards core
≥ 4.13.0 and writes `app.feeds`, which the published partial
`views/feed-link.pug` renders as `<link rel="alternate">` for the page's
language. `ROADMAP.md` (D1–D10, XML shapes, slices 1–7, release handover with
catalog snippets), README, CHANGELOG, fleet CI/husky/LICENSE; 110 tests incl.
four core-`run()` integration sites with every feed XML-validated.

## Decisions

- Language without a feed: a language with no entries gets no file and no warning; only when no language has any entry does the build warn once, naming `layouts` (D5).
- Undated posts: left out with one warning per build listing every href (D3/D4).
- Published date: frontmatter `date`, else `published` (Atom's name, common in imports); `createdAt` never. Updated: `updated`, `lastmod`, `updatedAt`, else published; an updated date before the published one counts as a typo and the published date is used (D4).
- Usable date strings: `YYYY-MM-DD` with optional `T`/space time and optional `Z`/`±hh:mm`; no offset = UTC; impossible calendar dates (`2026-02-30`) refused (D4).
- Language: `meta.lang`, else `app.lang`, else `en`; must match `^[A-Za-z]{1,8}(-[A-Za-z0-9]{1,8})*$` (path segment and `xml:lang`), other values skipped with one warning (D5).
- RSS item body: `<description>` = summary (`description`, else `lead`), else the full HTML; full HTML also in `content:encoded`; namespaces `atom`, `content`, `dc` always declared so the root line is stable (D7, XML shapes).
- Content is XML-escaped, never CDATA; XML-forbidden characters are dropped (D7).
- Ids are absolute URLs (feed URL, page URL), not tag URIs (D8).
- Feed title: config `title` (string or per-language mapping), else `app.name`, else origin host. Subtitle: config `subtitle`, else `app.translations[lang].app_description`, else none (RSS channel description falls back to the title). Feed author: config `author`, else `app.name`, else the title; entry author only from frontmatter `author` (a string); RSS uses `dc:creator` because `<author>` must be an e-mail (D8).
- Home link: the language's `index.html` when rendered, else `/` or `/<lang>/` (D8).
- Categories from `tags` (list or comma-separated string) (D8).
- App key name `app.feeds`: language → `[{ format, type, href (with base_path), url (absolute), title }]`, Atom first; `getAppData` computes it from the page list it sees and `getAssets` warns when links and written feeds disagree (pointing at `config/plugin-order.yaml` `end:`); no origin → `{}`. `getAppData` reads the config silently so each config warning appears once, from `getAssets` (D9).
- Partial: `views/feed-link.pug`, no classes, renders `app.feeds[meta.lang || app.lang || 'en']`; published as `npx nera-feed` (README leads with that, like plugin-tags) (D9).
- Added config key `exclude` (symmetry with sitemap); `title`/`subtitle` accept a string or a language mapping; `author` a string; no `output` key in 1.0 (O2) (D10).
- `getAssets` empties `.nera-cache/feed/` before writing (no stale per-language files).
- devDependencies `fast-xml-parser` (well-formedness) and `pug` (partial render test).

## Review hints

- `app.feeds` is computed in `getAppData`, before the `getMetaData` of plugins ordered after this one (D9, O4). The mismatch warning is the safety net; check that its advice (`end:` in `config/plugin-order.yaml`) is what you want to tell site owners.
- Content absolutizing is regex-based (`src/content.js`): unquoted attributes are skipped, and `\b(href|src|poster)=` also matches `data-src=`, `xlink:href=` (same as core's rewrite). Raw HTML in a post that contains a literal `href="…"` in text would be rewritten too (markdown-it escapes text quotes, so only hand-written raw HTML can).
- The README's `<link …>` example assumes a `doctype html` pug layout; the `nera new` layout starts with a literal `<!DOCTYPE html>` line, so there pug (and core's beautifier) write `<link … />` — harmless, but the markup differs.
- `homeHref` links `/index.html` (not `/`) when the index page is rendered, matching plugin-sitemap's choice of never shortening.
- Catalog descriptions (en/de/es) are mine; check the wording.
- Vitest 5 prints an informational "Isolate … faster with isolate: false" hint after the summary; it is Vitest's own performance tip, not a warning, so I left the config (and the per-file isolation the cwd-mocking tests rely on) alone.

## Not verified

- W3C Feed Validation Service (`validator.w3.org/feed/check.cgi`) — blocked by the proxy (CONNECT 403). Feeds were checked only by the shapes in RFC 4287 / RSS 2.0 as known, by fast-xml-parser's validator plus the helper's checks, and by `nera validate` on a real site.
- RFC 4287 and the RSS 2.0 spec were not fetched; the design relies on their known requirements (Atom: `id`, `title`, `updated` per feed and entry, an author at feed level, `link rel="alternate"` when there is no content; RSS: channel `title`/`link`/`description`).
